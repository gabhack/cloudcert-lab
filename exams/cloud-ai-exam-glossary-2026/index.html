Amazon Bedrock Guardrails vs AWS IAM

AWS IAM controls who can invoke Amazon Bedrock APIs at the infrastructure level, whereas Amazon Bedrock Guardrails inspects prompts and model outputs at runtime to block PII leakage, hallucinations (contextual grounding), prompt injection, and denied topics.

Exam Trap: Pick IAM for API access control; pick Bedrock Guardrails for content safety, PII redaction, or topic filtering.

RAG (Retrieval-Augmented Generation) vs Fine-Tuning

RAG injects fresh, verifiable private documents into the prompt at inference time via a vector store (Bedrock Knowledge Bases, Azure AI Search, Vertex AI Search) without modifying model weights, while fine-tuning updates weights to teach domain style, tone, or strict output formatting.

Exam Trap: Whenever a scenario mentions frequently changing data, citations, or lowest training cost, RAG beats fine-tuning.

Microsoft Foundry Hub vs Project (Azure AI-901)

In Microsoft Foundry, a Hub provides top-level enterprise governance, shared networking, Entra ID security, and Key Vault configuration, while individual Projects isolate workloads, datasets, prompt flows, and model endpoints for separate engineering teams.

Exam Trap: Share governance at the Hub level; isolate team workspaces and billing/RBAC inside separate Projects.

Slopsquatting & AI Package Hallucination Defense (AWS DVA-C03)

Slopsquatting occurs when attackers register non-existent package names repeatedly hallucinated by AI coding assistants on npm or PyPI. On AWS DVA-C03, teams defend against this using AWS CodeArtifact private upstream repositories, dependency lockfiles, and automated SCA scanning in CI/CD.

Exam Trap: Route all developer installs through AWS CodeArtifact with verified lockfiles rather than unrestricted public registries.

AWS Lambda SnapStart vs Provisioned Concurrency

Lambda SnapStart snapshots and caches the initialized execution environment (Firecracker microVM) for Java, Python, and .NET functions to slash cold starts by up to 90% at zero extra cost, whereas Provisioned Concurrency keeps warm containers running continuously for a fixed hourly fee.

Exam Trap: Choose SnapStart for cost-effective cold-start reduction on supported runtimes; choose Provisioned Concurrency only when strict sub-100ms tail latency or unsupported runtimes require it.

Google Cloud Grounding with Google Search vs Enterprise Data

Amazon S3 Tables & Apache Iceberg (AWS DEA-C01)

SageMaker Model Monitor vs SageMaker Clarify (AWS MLA-C01)

Amazon SageMaker Model Monitor continuously detects data drift, concept drift, and model quality degradation on live production endpoints, whereas SageMaker Clarify measures pre-training/post-training bias and computes SHAP feature explainability.

Exam Trap: Drift alerts in production = Model Monitor; fairness, demographic bias, or SHAP feature attribution = Clarify.

VPC Gateway Endpoint vs VPC Interface Endpoint (AWS SAA-C03)

A VPC Gateway Endpoint routes private traffic to Amazon S3 and DynamoDB via route table entries at $0 per hour and $0 data processing cost, while an Interface Endpoint (AWS PrivateLink) uses an ENI with private IP and hourly charges for 100+ other AWS services.

Exam Trap: For S3 or DynamoDB inside a VPC, always choose a Gateway Endpoint first for the lowest cost unless on-premises VPN/Direct Connect access requires an Interface Endpoint.

AWS Shared Responsibility Model (CLF-C02)

AWS is responsible for Security OF the Cloud (physical data centers, hardware, virtualization hypervisor, and managed service layers), while the customer is responsible for Security IN the Cloud (customer data encryption, IAM policies, security groups, and guest OS patching on EC2).

Exam Trap: Patching an EC2 guest OS = Customer; patching RDS/Lambda underlying OS = AWS; IAM users & S3 bucket policies = Customer.

DynamoDB GSI (Global Secondary Index) vs LSI (Local Secondary Index)

A Global Secondary Index (GSI) can be created or deleted anytime with a different partition key and independent throughput (eventual consistency only), whereas a Local Secondary Index (LSI) must be defined at table creation, shares the base partition key, and supports strongly consistent reads.

Exam Trap: Existing table needing a new query pattern = GSI; strongly consistent alternate sort key on a new table = LSI.

Amazon Bedrock Converse API vs InvokeModel (AWS AIP-C01 / DVA-C03)

The Bedrock Converse API provides a single unified request/response schema (including tool use, system prompts, and Guardrails) across Claude, Llama, Nova, and Mistral models, removing model-specific JSON payload rewrites required by raw InvokeModel calls.

Exam Trap: Whenever a question emphasizes portable multi-model switching or standardized tool calling on Bedrock, choose the Converse API.
