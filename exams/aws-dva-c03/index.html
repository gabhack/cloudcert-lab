Sample Q1 · Domain 1: Development with AWS Services SINGLE-SELECT

A financial services engineering team maintains 42 legacy Java 8 Maven microservices running on Amazon ECS and must upgrade them to Java 17 before an upcoming compliance audit. Senior developers want an AI-assisted workflow inside their IDE that automatically analyzes dependency trees, updates deprecated Jakarta EE APIs, compiles the project, and produces a reviewable diff so engineers can verify business logic before merging. Which AWS capability best meets this requirement?

  1. A. Enable Amazon CodeGuru Profiler on the running ECS tasks to automatically rewrite Java 8 bytecode into Java 17 compatible JAR archives during live traffic.
  2. B. Use Amazon Q Developer Agent for code transformation to automate the Java 8 to Java 17 migration, generate build-verified code diffs, and let developers review and approve the changes before committing.
  3. C. Export the Maven repositories to Amazon S3 and invoke Amazon Bedrock InvokeModel on each .java file independently without resolving pom.xml transitive dependencies.
  4. D. Configure AWS Elastic Beanstalk managed platform updates to upgrade the JVM runtime and rewrite deprecated javax package imports inside the compiled WAR files automatically.
Reveal Verified Answer (B), Technical Explanation & Exam Hack

Correct Answer: Option B

Option B is correct because Amazon Q Developer Agent for code transformation specifically automates Java 8/11 to Java 17/21 upgrades by inspecting the project structure, upgrading pom.xml dependencies, refactoring deprecated APIs, running Maven builds in a sandbox, and presenting a clear diff for human developer supervision prior to merge. Option A is wrong because CodeGuru Profiler analyzes runtime CPU and latency hotspots and never rewrites source code or upgrades language versions. Option C is wrong because sending isolated source files to a foundation model ignores multi-file dependency resolution and Maven compilation verification. Option D is wrong because Elastic Beanstalk platform updates change host runtimes but never refactor application source code or package imports.

Production Use Case: Enterprise platform teams use Amazon Q Developer code transformation to compress multi-quarter Java 8/11 modernization backlogs into days while keeping developers in control of pull request approvals and integration testing.
Exam Hack: Automated Java 8/11 to 17/21 upgrades with dependency resolution and reviewable diffs = Amazon Q Developer Agent for code transformation.
Sample Q2 · Domain 2: Security SINGLE-SELECT

During a pull request review for a new AWS Lambda support triage API generated with an AI coding assistant, a lead developer discovers two issues: the handler interpolates raw customer ticket text directly into a system prompt sent to Amazon Bedrock without input filtering, and it falls back to a hardcoded third-party CRM API key string when an environment variable is absent. Which remediation plan addresses both risks according to AWS security best practices?

  1. A. Base64-encode the fallback CRM API key inside the Python module and strip HTML tags from the customer ticket text using a regular expression before calling Bedrock.
  2. B. Remove the hardcoded fallback key, retrieve the CRM secret at runtime from AWS Secrets Manager using the Lambda execution role, separate system instructions from untrusted user content in the Bedrock Converse API, and attach Amazon Bedrock Guardrails with prompt attack filtering.
  3. C. Move the hardcoded CRM API key into the SAM template.yaml Parameters section with NoEcho enabled and increase the Bedrock model temperature to 0.9 to make prompt injection outputs less deterministic.
  4. D. Store the CRM API key in a public Amazon S3 bucket protected by an obscure object prefix and route all Bedrock calls through an AWS WAF rate-based rule.
Reveal Verified Answer (B), Technical Explanation & Exam Hack

Correct Answer: Option B

Option B is correct because it eliminates hardcoded credentials by fetching secrets dynamically from AWS Secrets Manager via least-privilege IAM, cleanly isolates system instructions from untrusted user messages in the Converse API, and enforces Amazon Bedrock Guardrails to detect and block prompt injection attacks. Option A is wrong because Base64 is reversible encoding rather than secret management, and HTML regex stripping does not stop natural-language prompt injection. Option C is wrong because NoEcho only masks CloudFormation console output rather than rotating or protecting secrets at runtime, and higher temperature worsens output unpredictability without mitigating prompt attacks. Option D is wrong because security by obscurity in a public S3 bucket violates least privilege and AWS WAF inspects HTTP traffic rather than semantic LLM prompt attacks.

Production Use Case: Security-conscious serverless teams combine AI code security reviews, AWS Secrets Manager runtime retrieval, and Amazon Bedrock Guardrails to harden AI-authored GenAI endpoints before production launch.
Exam Hack: Hardcoded fallback secret + prompt injection in AI-generated Lambda = Secrets Manager + separate Converse roles + Bedrock Guardrails prompt attack filter.
Sample Q3 · Domain 3: Testing and Deployment SINGLE-SELECT

A Python developer owns an AWS Lambda pricing engine that queries Amazon DynamoDB and publishes discount events to Amazon EventBridge. Unit test coverage sits at 34%, and many tax boundary conditions are untested. The developer wants to use AI-assisted test generation to rapidly create pytest unit tests that validate edge cases inside AWS CodeBuild without requiring live AWS credentials or incurring DynamoDB charges. What should the developer do?

  1. A. Enable AWS X-Ray active tracing on the Lambda function so X-Ray automatically generates and runs unit test suites whenever a new version is published.
  2. B. Configure AWS CodeBuild to provision a dedicated DynamoDB table and EventBridge bus on every git commit and invoke the live Lambda function in production with synthetic test payloads.
  3. C. Use Amazon Q Developer test generation to author pytest unit tests covering the uncovered branches, and mock Boto3 DynamoDB and EventBridge calls with botocore.stub.Stubber or moto so the suite executes offline in CodeBuild.
  4. D. Use Amazon Q Developer to disable conditional tax branches and rely solely on Amazon CloudWatch Synthetics Canaries after production deployment to catch pricing calculation bugs.
Reveal Verified Answer (C), Technical Explanation & Exam Hack

Correct Answer: Option C

Option C is correct because Amazon Q Developer can analyze function logic and generate targeted pytest unit tests for uncovered boundary conditions, while mocking AWS SDK calls with botocore Stubber or moto keeps unit tests fast, deterministic, credential-free, and cost-free inside CodeBuild. Option B is wrong because provisioning real cloud resources on every unit test run is slow and costly, and invoking production with synthetic payloads risks corrupting live data. Option A is wrong because AWS X-Ray traces live distributed requests and never generates unit tests. Option D is wrong because deleting business logic and relying exclusively on post-deploy canaries lets critical pricing defects reach customers.

Production Use Case: Serverless engineering teams pair Amazon Q Developer unit test generation with botocore Stubber or moto in CodeBuild to raise branch coverage above 80% with sub-second offline test execution.
Exam Hack: AI-assisted offline unit tests for Boto3 Lambdas in CodeBuild = Amazon Q Developer test generation + botocore Stubber or moto mocks.
Sample Q4 · Domain 4: Troubleshooting and Optimization SINGLE-SELECT

An e-commerce API backed by 14 AWS Lambda microservices experiences sporadic HTTP 504 timeouts during flash sales. On-call developers struggle to write complex regex queries across all 14 log groups to correlate requestId values, cold start init durations from REPORT lines, and downstream latency spikes. Which approach enables the fastest unified root-cause investigation?

  1. A. Download each Lambda log stream manually from the AWS Management Console as CSV files and search them sequentially on a local laptop using grep.
  2. B. Switch all 14 Lambda functions from standard JSON logging to unstructured plain-text print statements so CloudWatch Metrics can automatically graph requestId timeouts.
  3. C. Export every CloudWatch Log group to Amazon S3 Glacier Deep Archive every hour and inspect the archives with Amazon S3 Select.
  4. D. Select all 14 Lambda log groups in Amazon CloudWatch Logs Insights and use natural-language query generation (or Amazon Q Developer operational investigation) to build a multi-log-group query correlating requestId, Init Duration, and timeout entries.
Reveal Verified Answer (D), Technical Explanation & Exam Hack

Correct Answer: Option D

Option D is correct because CloudWatch Logs Insights natively queries up to dozens of log groups simultaneously and supports natural-language query generation (alongside Amazon Q Developer investigations) to rapidly synthesize fields, filter, parse, and stats queries that correlate requestId values, Init Duration spikes, and timeout errors. Option A is wrong because manual downloads and local grep do not scale during an active incident. Option C is wrong because S3 Glacier Deep Archive has hours-long retrieval times and cannot be queried interactively for live incident triage. Option B is wrong because unstructured print statements degrade queryability compared to structured JSON logs and CloudWatch Metrics does not automatically graph arbitrary requestId strings.

Production Use Case: SRE and backend teams query correlated serverless microservices in seconds using CloudWatch Logs Insights natural-language query generation across multiple Lambda log groups.
Exam Hack: Correlate requestId and Init Duration across many Lambda log groups quickly = CloudWatch Logs Insights multi-log-group query with natural-language generation.
Sample Q5 · Domain 1: Development with AWS Services SINGLE-SELECT

A SaaS analytics startup is building a Python FastAPI service on AWS Fargate that integrates with Amazon Bedrock to stream answers to browser clients in real time and invoke internal SQL lookup tools. Product managers want the flexibility to switch between Anthropic Claude and Amazon Nova models by changing only a modelId configuration value, without rewriting request body schemas or parsing logic. Which Boto3 Bedrock Runtime pattern should the developer implement?

  1. A. Call bedrock-runtime invoke_model with model-specific JSON payload templates for each provider and buffer the entire completion in memory before returning HTTP 200.
  2. B. Call bedrock-runtime converse_stream with a standardized messages array and toolConfig definition so streaming token deltas and tool-use blocks follow one uniform schema across supported foundation models.
  3. C. Invoke bedrock-agent start_ingestion_job on every user chat turn so Bedrock transforms model responses into uniform CSV chunks.
  4. D. Use Amazon API Gateway VTL mapping templates to translate Anthropic JSON schemas into Amazon Nova schemas inside a REST API proxy without modifying the Fargate code.
Reveal Verified Answer (B), Technical Explanation & Exam Hack

Correct Answer: Option B

Option B is correct because the Amazon Bedrock Converse API (specifically converse_stream for streaming) provides a single, consistent request and response schema across supported foundation models, including multi-turn messages, system prompts, guardrails, and toolConfig function calling, letting developers swap modelId without code rewrites. Option A is wrong because invoke_model requires provider-specific payload formats and buffering defeats real-time token streaming. Option C is wrong because start_ingestion_job indexes documents into a Knowledge Base rather than executing real-time streaming chat completions. Option D is wrong because VTL mapping templates in API Gateway cannot handle bi-directional streaming event streams cleanly and add brittle translation logic that Converse eliminates natively.

Production Use Case: Multi-model GenAI backends standardize on Bedrock converse and converse_stream so product teams can A/B test or upgrade foundation models via a single modelId environment variable.
Exam Hack: One uniform API for streaming + tool use across multiple Bedrock models = bedrock-runtime converse_stream.
