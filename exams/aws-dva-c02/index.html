Sample Q1 · Domain 1: Development with AWS Services SINGLE-SELECT

At a mobile FinTech startup, the cloud development team is building a serverless document-upload feature where authenticated mobile app users upload 250 MB PDF statements directly to a private Amazon S3 bucket (bypassing API Gateway's 10 MB payload limit). Select and order the 4 architectural steps from login to direct S3 upload.

  1. A. Order 1 -> 2 -> 3 -> 4: (1) Authenticate the mobile user against an Amazon Cognito User Pool and receive a signed JWT ID/Access token -> (2) Call an Amazon API Gateway REST endpoint (protected by a Cognito User Pool Authorizer) that invokes an AWS Lambda function -> (3) Have the Lambda function (whose Execution Role holds `s3:PutObject` permission) call the S3 SDK `generate_presigned_url('put_object')` with a 15-minute expiration and return the URL to the client -> (4) Have the mobile client perform an HTTP `PUT` of the 250 MB file directly to Amazon S3 using the Pre-Signed URL.
  2. B. Order 4 -> 3 -> 2 -> 1: (1) Upload the 250 MB PDF directly through API Gateway -> (2) Invoke Lambda -> (3) Generate a Pre-Signed URL after upload -> (4) Authenticate with Cognito last.
  3. C. Order 1 -> 3 -> 4 -> 2: (1) Authenticate with Cognito -> (2) Embed static IAM root access keys inside the mobile app binary -> (3) Upload to S3 -> (4) Call API Gateway.
  4. D. Order 2 -> 1 -> 3 -> 4: (1) Call API Gateway unauthenticated -> (2) Make the S3 bucket completely public -> (3) Generate a Pre-Signed URL with no IAM permissions -> (4) Upload via SQS.
Reveal Verified Answer (A), Technical Explanation & Exam Hack

Correct Answer: Option A

Because Amazon API Gateway enforces a hard 10 MB payload ceiling and 29-second timeout, large binary uploads always authenticate via Cognito (Step 1), request a short-lived S3 Pre-Signed URL from a Lambda function whose Execution Role has `s3:PutObject` permission (Steps 2-3), and upload directly from the client to S3 via HTTP PUT (Step 4). Architectural Deep Dive: AWS Lambda executes serverless functions up to 15 minutes with 128 MB to 10 GB memory, 512 MB to 10 GB /tmp ephemeral storage, Lambda Layers for shared libraries/dependencies across functions, Provisioned Concurrency (or Lambda SnapStart for Java/Python/.NET) to eliminate cold starts, and Reserved Concurrency to guarantee and cap maximum concurrent executions for a specific function. Why Distractors Fail: Option B (Order 4 -> 3 -> 2 -> 1: (1) Upload the 250 MB PDF directly through API Gate...) is incorrect because that service applies to a different workload pattern and confuses Reserved Concurrency (which throttles/caps concurrency and does NOT pre-warm execution environments) with Provisioned Concurrency (which pre-warms environments to eliminate cold-start latency). Option C (Order 1 -> 3 -> 4 -> 2: (1) Authenticate with Cognito -> (2) Embed static I...) is incorrect because that service applies to a different workload pattern and exceeds API Gateway's hard 29-second integration timeout or 10 MB payload ceiling instead of using S3 Pre-Signed URLs for large file uploads or asynchronous invocation patterns. Option D (Order 2 -> 1 -> 3 -> 4: (1) Call API Gateway unauthenticated -> (2) Make th...) is incorrect because that service applies to a different workload pattern and exceeds API Gateway's hard 29-second integration timeout or 10 MB payload ceiling instead of using S3 Pre-Signed URLs for large file uploads or asynchronous invocation patterns.

Production Use Case: Latency-sensitive checkout APIs configure an Application Auto Scaling schedule on Lambda Provisioned Concurrency (pointed at a published function Version or Alias, never $LATEST) ahead of flash sales.
Exam Hack: Eliminate Lambda cold starts = Provisioned Concurrency (or SnapStart for Java) on a Version/Alias. Cap a function so it doesn't overwhelm a downstream RDS DB = Reserved Concurrency. Share common SDKs/certs across functions = Lambda Layers.

The application handles the failure scenarios and does not require standby workers. The application reports that a specific shard is receiving more data than expected. To adapt to the changes in the rate of data flow, the `hot` shard is resharded. Sample Q5 · Domain 2: Security SINGLE-SELECT

A digital banking engineering squad enforcing strict zero-trust security and CI/CD governance on AWS has a developer who manages an environment that has 25,000 employees and is growing. The enterprise is creating an application that will be accessible to its employees only. A developer is using Amazon S3 to store images and Amazon RDS to store application data. The enterprise requires that all employee information remain in the legacy Security Assertion Markup Language (SAML) employee directory only and is not interested in mirroring any employee information on AWS. How can the cloud engineer provide authorized access for the employees who will be using this application so each employee can access their own application data only?

  1. A. Use Amazon VPC and keep all resources inside the VPC, and use a VPC link for the S3 bucket with the bucket policy.
  2. B. Use Amazon Cognito user pools, federate with the SAML provider, and use user pool groups with an IAM policy.
  3. C. Implement the workflow using a Amazon Cognito identity pool, federate with the SAML provider, and use an IAM condition key with a value for the `cognito-identity.amazonaws.com:sub` variable to grant access to the employees.
  4. D. Establish and deploy a unique IAM role for each employee and have each employee assume the role to access the application so they can access their personal data only.
Reveal Verified Answer (C), Technical Explanation & Exam Hack

Correct Answer: Option C

Correct Answer (C): Option C (Implement the workflow using a Amazon Cognito identity pool, federate with the SAML provider, and use an IAM condition key with a value for the `cognito-identity.amazonaws.com:sub` variable to grant access to the employees.). Amazon Cognito separates authentication from AWS resource authorization: Cognito User Pools are managed user directories that handle sign-up, sign-in, MFA, SAML/OIDC social federation, and issue JWT tokens (ID/Access/Refresh) for API Gateway/ALB; Cognito Identity Pools (Federated Identities) exchange a valid login token for temporary, scoped AWS IAM credentials via AWS STS so mobile/web clients can access S3 or DynamoDB directly. Furthermore, AWS SAM (Serverless Application Model) extends CloudFormation (`Transform: AWS::Serverless-2016-10-31`) to define serverless apps concisely (`AWS::Serverless::Function`, `SimpleTable`, `Api`), supports local testing (`sam local invoke`, `sam local start-api`), uses the `Globals` section to avoid repeating shared properties (Runtime, Timeout, Tracing), and integrates natively with AWS CodeDeploy (`AutoPublishAlias` + `DeploymentPreference` like `Canary10Percent10Minutes` or `Linear10PercentEvery1Minute` with `PreTraffic` and `PostTraffic` Lambda hooks). Why Distractors Fail: Option A (Use Amazon VPC and keep all resources inside the VPC, and use a VPC link fo...) is incorrect because that service applies to a different workload pattern and hardcodes plaintext credentials inside `buildspec.yml` or forgets to configure CodeBuild VPC subnet/NAT settings when build tests must reach private RDS databases. Option B (Use Amazon Cognito user pools, federate with the SAML provider, and use use...) is incorrect because that service applies to a different workload pattern and exceeds API Gateway's hard 29-second integration timeout or 10 MB payload ceiling instead of using S3 Pre-Signed URLs for large file uploads or asynchronous invocation patterns. Option D (Establish and deploy a unique IAM role for each employee and have each empl...) fails to satisfy the specific performance, security, or managed-service constraint stated in the prompt.

Production Use Case: A mobile photo app authenticates users via a Cognito User Pool (or Google/Apple login) and then exchanges that token at a Cognito Identity Pool to obtain temporary STS credentials restricted by an IAM policy using ${cognito-identity.amazonaws.com:sub} to the user's own S3 prefix.
Exam Hack: Need JWT tokens for API Gateway/ALB login? -> Cognito User Pool. Need temporary AWS IAM credentials for mobile/browser clients to access S3/DynamoDB directly? -> Cognito Identity Pool.
