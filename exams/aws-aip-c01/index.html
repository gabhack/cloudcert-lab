Sample Q1 · Domain 1: Foundation Model Integration, Data Management & Compliance (31%) SINGLE-SELECT

A pharmaceutical company wants to build an internal GenAI assistant that answers regulatory compliance questions across 18,000 FDA guidance PDFs updated weekly. Legal leadership requires inline citations pointing to the exact source document and page, and mandates zero model retraining when new regulations are published. Which adaptation strategy should the architect choose?

  1. A. Paste the entire corpus of 18,000 PDFs into the system prompt of every Converse API request using Prompt Caching.
  2. B. Run weekly Continued Pre-Training jobs in Amazon Bedrock on all 18,000 PDFs so the model memorizes the latest statutes.
  3. C. Fine-tune a foundation model with Supervised Fine-Tuning every Friday using automatically generated question-answer pairs from the PDFs.
  4. D. Implement Retrieval-Augmented Generation using Amazon Bedrock Knowledge Bases backed by Amazon S3 and an OpenSearch Serverless vector store with incremental sync.
Reveal Verified Answer (D), Technical Explanation & Exam Hack

Correct Answer: Option D

Option D is correct because RAG with Amazon Bedrock Knowledge Bases grounds answers in live S3 documents, provides native inline source citations, and updates incrementally in minutes via StartIngestionJob without retraining. Option B is wrong because Continued Pre-Training is expensive, slow, and cannot produce reliable document citations or handle weekly updates. Option C is wrong because Supervised Fine-Tuning is designed for style and format adaptation rather than dynamic factual recall. Option A is wrong because 18,000 PDFs vastly exceed any foundation model context window.

Production Use Case: Regulated life-sciences teams deploy Bedrock Knowledge Bases to serve auditable, cited answers over frequently changing FDA and EMA guidance documents.
Exam Hack: Weekly changing facts + source citations + zero retraining = RAG via Bedrock Knowledge Bases.
Sample Q2 · Domain 1: Foundation Model Integration, Data Management & Compliance (31%) SINGLE-SELECT

A global manufacturing enterprise is ingesting 40,000 complex equipment service manuals into an Amazon Bedrock Knowledge Base. The PDFs contain dense multi-column wiring tables, schematics, and embedded flowcharts. After testing standard text chunking, engineers discover that table columns are scrambled and chart data is missing completely. Which AWS capability resolves this ingestion defect with minimal custom code?

  1. A. Switch the embedding model from Amazon Titan Text Embeddings V2 to Cohere Embed English.
  2. B. Reduce fixed-size chunk length from 500 tokens to 100 tokens with 50 percent overlap.
  3. C. Enable Amazon Bedrock Data Automation or the Bedrock Foundation Model Parser during Knowledge Base ingestion to parse tables, charts, and visual layouts into structured text.
  4. D. Convert all PDFs into raw Base64 strings and store them directly inside OpenSearch Serverless metadata fields.
Reveal Verified Answer (C), Technical Explanation & Exam Hack

Correct Answer: Option C

Option C is correct because Amazon Bedrock Data Automation and the Bedrock Foundation Model Parser visually analyze complex PDFs, preserving multi-column table geometry, diagrams, and charts as clean structured Markdown or JSON before chunking. Option B is wrong because smaller fixed chunks worsen scrambled text without fixing layout extraction. Option A is wrong because changing the embedding model cannot recover text or charts that the parser failed to extract. Option D is wrong because Base64 strings are not semantically searchable by vector embeddings.

Production Use Case: Industrial equipment makers use Bedrock Data Automation to index complex engineering schematics and multi-column maintenance tables accurately.
Exam Hack: Scrambled PDF tables and missing charts in KB ingestion = Bedrock Data Automation or FM Parser.
Sample Q3 · Domain 1: Foundation Model Integration, Data Management & Compliance (31%) SINGLE-SELECT

An insurance carrier's Knowledge Base indexes 12,000 multi-section policy handbooks. Engineers find that small 250-token fixed chunks match user queries accurately during vector search, yet the LLM frequently gives incomplete answers because critical policy exclusions sit in the adjacent paragraph. Larger 1,500-token chunks fix the context issue but cause retrieval precision to drop sharply. Which chunking strategy solves both problems simultaneously?

  1. A. Configure Hierarchical Chunking in Amazon Bedrock Knowledge Bases so small child chunks are indexed for high-precision retrieval while their larger parent chunks are passed to the foundation model.
  2. B. Increase top-k retrieval from 5 to 60 small chunks and disable metadata filtering.
  3. C. Switch from cosine similarity to Euclidean distance inside the vector database.
  4. D. Disable chunking entirely and embed every 80-page handbook as a single vector record.
Reveal Verified Answer (A), Technical Explanation & Exam Hack

Correct Answer: Option A

Option A is correct because Hierarchical Chunking indexes fine-grained child chunks for precise semantic matching and automatically retrieves the encompassing parent chunk so the LLM receives complete surrounding exclusions and context. Option D is wrong because embedding entire 80-page handbooks dilutes semantic vectors and overflows context budgets. Option B is wrong because stuffing 60 tiny chunks triggers the Lost in the Middle effect and spikes input token costs. Option C is wrong because distance metrics cannot restore missing adjacent paragraphs.

Production Use Case: Insurance and legal RAG systems adopt Hierarchical Chunking to keep pinpoint search recall while delivering full clause context to the generator.
Exam Hack: High precision of small chunks + full context of large chunks = Hierarchical Chunking.
Sample Q4 · Domain 1: Foundation Model Integration, Data Management & Compliance (31%) SINGLE-SELECT

A FinTech company stores customer portfolio entitlements and account roles in Amazon Aurora PostgreSQL. The team wants to build a RAG assistant over financial research notes where every vector similarity query must execute an ACID-consistent SQL join against the live relational entitlement tables to enforce row-level access controls. Which vector store architecture fits best?

  1. A. Amazon OpenSearch Serverless with a nightly AWS Glue export of Aurora entitlement tables.
  2. B. Amazon Neptune Analytics GraphRAG synchronized via DynamoDB Streams.
  3. C. Amazon S3 Vectors queried directly through Amazon Athena federated queries.
  4. D. Amazon Aurora PostgreSQL with the pgvector extension and an HNSW vector index.
Reveal Verified Answer (D), Technical Explanation & Exam Hack

Correct Answer: Option D

Option D is correct because Aurora PostgreSQL with pgvector lets the application store embeddings alongside relational entitlement tables and execute single-query transactional SQL joins with HNSW vector search for real-time row-level security. Option A is wrong because nightly exports introduce up to 24 hours of stale authorization risk. Option C is wrong because S3 Vectors does not execute transactional ACID joins with Aurora tables. Option B is wrong because Neptune Analytics is designed for graph traversal rather than relational PostgreSQL entitlement joins.

Production Use Case: FinTech platforms leverage Aurora PostgreSQL pgvector when strict real-time relational RBAC joins must be combined with low-latency HNSW vector search.
Exam Hack: Transactional SQL joins + existing relational RBAC + vectors = Aurora PostgreSQL pgvector with HNSW.
Sample Q5 · Domain 1: Foundation Model Integration, Data Management & Compliance (31%) SINGLE-SELECT

A European supply-chain firm wants a GenAI system that uncovers hidden multi-hop risks across 25,000 supplier contracts, purchase orders, and logistics incident reports, such as identifying which Tier-1 electronics vendors indirectly depend on a disrupted Tier-3 mineral refiner. Standard flat vector search fails because no single document mentions both the Tier-1 vendor and the Tier-3 refiner. Which Bedrock Knowledge Bases architecture solves this?

  1. A. Configure GraphRAG in Amazon Bedrock Knowledge Bases backed by Amazon Neptune Analytics to extract and traverse entity relationships across documents.
  2. B. Increase fixed chunk overlap to 40 percent inside Amazon OpenSearch Serverless.
  3. C. Switch to a smaller 256-dimension embedding model with binary quantization.
  4. D. Use Amazon S3 Select to run SQL LIKE queries across the raw contract PDFs.
Reveal Verified Answer (A), Technical Explanation & Exam Hack

Correct Answer: Option A

Option A is correct because GraphRAG with Amazon Neptune Analytics automatically builds a knowledge graph of entities and relationships across the entire corpus, enabling multi-hop traversal from Tier-1 vendors through Tier-2 sub-assemblies to Tier-3 refiners. Option B is wrong because chunk overlap only helps adjacent text inside a single document. Option D is wrong because S3 Select does not parse PDFs or perform multi-hop graph reasoning. Option C is wrong because reducing embedding dimensions saves memory but cannot link entities across separate files.

Production Use Case: Enterprise procurement and intelligence teams use Neptune Analytics GraphRAG to surface multi-hop vendor, legal, and compliance dependencies.
Exam Hack: Multi-hop entity relationships across separate documents = GraphRAG with Amazon Neptune Analytics.
